# 开发与构建说明

本文记录源码结构、编译方法、常见修改位置与脚本用法。运行方式与输出格式见 `README.md`。

## 一、环境

| 平台 | 需要的东西 |
| --- | --- |
| Linux | 支持 C++17 的 g++ 或 clang++，CMake 3.16 及以上 |
| Windows | Visual Studio 2019 及以上的 C++ 生成工具（cl.exe），或 MinGW-w64；CMake 3.16 及以上 |

代码只用标准库，不依赖 POSIX 头文件，也不用第三方库。

## 二、源码结构

| 文件 | 职责 |
| --- | --- |
| `lexer/include/lexer/token.hpp`、`lexer/src/token.cpp` | 种别码枚举、记号结构、二元式格式化 |
| `lexer/include/lexer/keyword_table.hpp`、`lexer/src/keyword_table.cpp` | 保留字有序表与查表接口 |
| `lexer/include/lexer/diagnostic.hpp`、`lexer/src/diagnostic.cpp` | 诊断码、错误收集、带插入符的呈现 |
| `lexer/include/lexer/lexer.hpp`、`lexer/src/lexer.cpp` | 游标推进、字符分类、各类子扫描器 |
| `lexer/src/main.cpp` | 读文件、循环取记号、输出与退出码 |

依赖方向单向：`main` 依赖 `lexer`，`lexer` 依赖 `token`、`keyword_table`、`diagnostic`。

## 三、编译

### Linux

```bash
cmake -S lexer -B lexer/build -DCMAKE_BUILD_TYPE=Release
cmake --build lexer/build -j
```

产物为 `lexer/build/lexer`。

默认静态链接，生成的程序换机器运行不需要装运行库。若要改成动态链接：

```bash
cmake -S lexer -B lexer/build -DLEXER_STATIC=OFF -DCMAKE_BUILD_TYPE=Release
```

### Windows

用 MSVC：

```bat
cmake -S lexer -B lexer\build
cmake --build lexer\build --config Release
```

产物为 `lexer\build\Release\lexer.exe`。`LEXER_STATIC=ON` 时 MSVC 使用 `/MT`，不依赖 VC++ 运行库；用 MinGW 时对应 `-static`。

也可以直接运行 `lexer\run.bat`，它在找不到可执行文件时会自己调用上面两条命令。

## 四、常见修改位置

| 想改的内容 | 位置 |
| --- | --- |
| 增删保留字 | `lexer/src/keyword_table.cpp` 的常量数组，保持字典序，二分查找依赖它 |
| 单字符运算符集合 | `lexer/src/lexer.cpp` 的 `isSingleOperator` |
| 双字符运算符 | `lexer/src/lexer.cpp` 的 `kTwoCharOperators` |
| 数字的进制、后缀规则 | `scanNumber` |
| 字符常量的转义与闭合判定 | `scanChar` |
| 字符串常量的规则 | `scanString` |
| 三种注释的跳过方式 | `skipBraceComment`、`skipLineComment`、`skipBlockComment` |
| 诊断码与文案 | 各扫描函数中的 `diagnostics_.add`，编码含义见 `README.md` 的诊断表 |
| 二元式的写法 | `lexer/src/token.cpp` 的 `formatToken` |
| 回显、对齐与统计 | `lexer/src/main.cpp` 的输出段落与 `Stats` 结构 |

改完重新编译一次即可，测试用例会给出回归结果。

## 五、脚本

| 脚本 | 用途 |
| --- | --- |
| `lexer/run.sh`、`lexer/run.bat` | 运行。优先使用 `bin` 中的产物，其次 `build`，都没有才调用 CMake 构建 |
| `lexer/tests/run_tests.sh`、`lexer/tests/run_tests.bat` | 逐用例比对期望输出。Linux 用 `diff`，Windows 用 `fc /b` |
| `scripts/package.sh`、`scripts/package.bat` | 静态 Release 构建、跑测试、铺 `dist` 目录、压缩成 zip 并生成 `CHECKSUMS.txt` |

测试脚本支持用环境变量 `LEXER_BIN` 指定被比较的可执行文件，便于对预编译产物做检查。

## 六、可执行文件的放置

| 文件 | 说明 |
| --- | --- |
| `lexer/bin/lexer-linux-x86_64` | Linux x86_64，静态链接 |
| `lexer/bin/lexer-windows-x86_64.exe` | Windows x86_64，用 MSVC 或 MinGW 编出后放在此处 |

查找顺序：`run.sh` 依次找 `bin/lexer-linux-*`、`bin/lexer`、`build/lexer`；`run.bat` 依次找 `bin\lexer-windows-x86_64.exe`、`bin\lexer.exe`、`build\Release\lexer.exe`、`build\lexer.exe`。

## 七、跨平台一致性

同一份源程序在两个平台上的输出逐字节相同，测试期望输出因此可以共用一套。做法有四处：

- 源文件按二进制读入，不经文本模式，避免换行被自动转换。
- `\r\n`、单独的 `\r` 与 `\n` 都按一个换行计，行号与切分规则一致。
- Windows 端启动时把标准输出切到二进制模式，`\n` 不会被改写成 `\r\n`。
- Windows 端把控制台代码页设为 UTF-8，并用宽字符入口接收参数，中文路径与中文诊断都能正常显示。

```bash
./tests/run_tests.sh

```
