# c-lexer

《编译技术》实验一的作业：一个 C 语言子集的词法分析器。

把 `.c` 文件交给它，它会按行列出每个单词属于哪一类，也就是课程里说的二元式；注释和空白会被删掉，写错的地方会指出在第几行第几列。

## 包里有什么

| 位置 | 内容 |
| --- | --- |
| `lexer/src`、`lexer/include` | 全部源代码 |
| `lexer/bin` | 编译好的程序，解压就能跑 |
| `lexer/examples` | 两个可以直接跑的小例子 |
| `lexer/tests` | 测试用例、期望输出和比对脚本 |
| `docs` | 使用说明、测试结果 |
| `report/out` | 实验报告 PDF |

# 使用说明

## 方式一：下载就能用（推荐）

不需要装编译器，也不需要懂命令。

1. 打开本仓库的 Releases 页面，下载 `lexer-1.0-linux-x86_64.zip`。
2. 解压到任意目录。
3. 打开终端，进入解压出来的文件夹。
4. 敲这一行，把文件名换成你自己的：

```bash
./bin/lexer-linux-x86_64 你的文件.c
```

不确定从哪下手，先用包里自带的例子试一下：

```bash
./bin/lexer-linux-x86_64 examples/simple.c
```

能打出结果，就说明程序是好的。

## 方式二：自己编译

改过代码，或者想在自己电脑上重新编一份，就用这一组命令：

```bash
cmake -S lexer -B lexer/build
cmake --build lexer/build -j
```

编完运行：

```bash
lexer/build/lexer 你的文件.c
```

嫌命令长的话，用 `./lexer/run.sh 你的文件.c` 也一样。它会先看有没有编好的程序，没有就自动帮你编，编完接着跑。

Windows 上用 `lexer\run.bat 你的文件.c`，第一次运行会自动编译，前提是电脑里装了 CMake 和 Visual Studio 的 C++ 工具，或者 MinGW。

## 跑完看到什么

```
=== 你的文件.c ===
  3 |     int a = 12;
    | (6,"int") (1,"a") (7,"=") (2,"12") (7,";")
```

上面那行是原程序，前面加了行号。下面缩进的那行是这一行里的单词，括号里第一个数字是类别，第二个是它本身。

类别对照：

| 数字 | 意思 |
| --- | --- |
| 1 | 标识符，比如变量名 |
| 2 | 整数 |
| 3 | 小数 |
| 4 | 字符，比如 `'x'` |
| 5 | 字符串 |
| 6 | 关键字，比如 `int`、`while` |
| 7 | 运算符，以及括号、分号 |
| 9 | 这里写错了 |

最后还有一段统计，告诉你一共多少行、多少个单词、几处错误。

## 写错了会怎样

程序不会中途停，会把错误一处一处列出来，并指出位置：

```
你的文件.c:1:9: E101 非法字符：#
  1 | int a = #;
    |         ^
```

`^` 指着的那个字符就是出问题的地方。完整的错误码见 `docs/使用说明.md`。

## 能不能分析我自己的代码

可以，前提是代码只用课程要求里出现过的写法。`#include`、数组的方括号、逗号、指针的 `->` 这些符号不在要求里，用到会报“非法字符”，这是照着指导书故意设的。

## 常见问题

**想知道程序有没有被改坏**
跑一遍自带的测试就行，七个用例全过就正常：

```bash
cd lexer
./tests/run_tests.sh
```

**输出太长，想存下来**
重定向到文件即可：

```bash
./bin/lexer-linux-x86_64 你的文件.c > 结果.txt
```

**路径里有中文**
可以用，程序内部按 UTF-8 处理。

**怎么看有没有错误**
看最后的“错误：”后面的数字，是 0 就没错。程序结束时也会返回一个值，0 表示没问题，1 表示有错误，方便写脚本时判断。
